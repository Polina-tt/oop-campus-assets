## Призначення класу EquipmentItem
Клас EquipmentItem призначений для безпечного представлення та обліку університетського обладнання. Він замінює собою структуру даних з Лабораторної роботи №1, повністю інкапсулює внутрішній стан та забезпечує суворий контроль над допустимими переходами об'єкта.

## Перелік інваріантів класу
1. Ідентифікатор об'єкта (id) обов'язково повинен бути більшим за нуль.
2. Назва обладнання (name) не може бути порожнім рядком.
3. Категорія обладнання (category) не може бути порожнім рядком.
4. Нове обладнання при створенні автоматично переходить у початковий стан Available (Доступне).

## Допустимі переходи стану
* Available -> InUse (Видача обладнання)
* InUse -> Available (Повернення обладнання)
* Available -> UnderMaintenance (Передача на технічне обслуговування)
* UnderMaintenance -> Available (Завершення обслуговування)
* Будь-які інші переходи суворо відхиляються логікою класу та викликають виняток.

## Використані аналізатори та обґрунтування
У проєкті налаштовано та використано такі інструменти якості коду:
1. **GCC warnings (-Wall -Wextra -Werror)** — знаходить помилки на етапі компіляції та забороняє збірку проєкту за наявності попереджень.clang-formatat** — перевіряє дотримання стилю кодування (відступи 4 пробіли, обмеження рядка).Cppcheckck** — здійснює незалежний статичний аналіз вихідного коду на наявність логічних помилок.Clang-Tidydy** — глибокий лінтер. Використано такі обов'язкові групи:
   * clang-analyzer-* — для пошуку критичних дефектів (витоки пам'яті, розіменування нулів).
   * bugprone-* — для пошуку конструкцій коду, які легко призводять до прихованих багів.
   * performance-* — для виявлення неефективного використання пам'яті та копіювань.
